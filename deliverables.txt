1. CORE CAPABILITIES (WHAT THE SYSTEM DOES)
-----------------------------------------------------------------------------

At the end of building, the System Resource Optimizer successfully performs the following live desktop operations:

[A] Real-Time Telemetry Collection & Feature Engineering
    - Polls system telemetry at a highly accurate rate of 1Hz (1 sample per second) using a non-blocking system API (psutil).
    - Collects 8 core features (Overall CPU %, CPU Frequency, Physical Memory Used, Memory Available, Memory %, Swap Used, Swap %, and CPU Package Temperature) plus dynamic per-core CPU utilization loads.
    - Resolves physical hardware limitations (common on VMs and Windows) by querying physical ACPI thermal sensor registers or seamlessly falling back to a first-order lag filter ThermalSimulator to model thermal inertia.
    - Applies an Exponential Moving Average (EMA) with an alpha coefficient of 0.3 to raw CPU and memory metrics to eliminate telemetry spike noise.
    - Tracks Net Upload/Download speeds, Disk Read/Write speeds, system uptime, and total running process counts to build a rich telemetry matrix.

[B] AI-Powered Bottleneck Prediction (1Hz Inference Loop)
    - Integrates a lightweight, quantized Gated Recurrent Unit (GRU) neural network model (INT8 quantized ONNX, size ~0.17 MB) running on a single background thread.
    - Operates with an extremely low CPU overhead (less than 2% system usage) ensuring the optimizer itself never becomes a resource bottleneck.
    - Restores temporal history by feeding a 60-second historical sequence sliding window into the GRU model every second.
    - Predicts the system load state 30 seconds into the future, outputting:
        * A Bottleneck Confidence Score (0.0 to 1.0) indicating system failure risk.
        * Predicted CPU % load at the 30-second future horizon.
        * Predicted Memory % load at the 30-second future horizon.
    - Falls back to a reactive heuristic algorithm (CPU spike scaling + trend boosting) if the neural network file is missing or unreadable.

[C] Safe Processes Autopilot & Action Engine
    - Employs an intelligent process control system to optimize active resources.
    - Implements an "Autopilot Mode" which automatically triggers optimization events if the AI bottleneck confidence reaches or exceeds 80% (limited by a 45-second safety cooldown).
    - Protects the OS by checking target processes against a strict System Whitelist (shielding core Windows services, kernel operations, desktop windows managers, security apps, and the optimizer executable itself).
    - Automatically suspends the top 3 resource-consuming, non-whitelisted background processes using thread-safe OS commands.
    - Houses an active safety watchdog that auto-resumes all suspended processes after a 5-minute timeout, ensuring no user software is permanently locked.

[D] Hardware Domain Adaptation (Local Calibration)
    - Automatically executes a silent 90-second hardware calibration routine upon the first run of the application on any new computer.
    - Learns the baseline range of the local hardware (compensating for divergence in CPU core counts, RAM capacity, and thermal boundaries).
    - Fits and serializes a local MinMaxScaler (~/.sro_optimizer/scaler_local_v2.pkl) to ensure out-of-distribution system loads do not skew AI predictions.

[E] High-Fidelity Glassmorphic User Interface
    - Delivers a premium, GPU-accelerated dashboard styled with a modern Dark Glassmorphic layout using Flet.
    - Features a 260px left-hand navigation sidebar linking three distinct functional pages:
        * Dashboard: Displays the AI Bottleneck Gauge, live telemetry cards, three real-time rolling canvas charts, a live processes table (top 20 consumers updated every 3 seconds), manual action buttons (One-Click Boost, Undo), and an active system log.
        * Analytics: Details prediction matrices, active risk indexes, and feature vectors.
        * Settings: Configurations for autopilot rules, thresholds, and calibration.
    - Avoids race conditions and GUI freezes by using an atomic thread lock which prevents concurrent UI updates from colliding during Flet canvas painting cycles.

3. SYSTEM GUARANTEES & ACADEMIC OUTCOMES
-----------------------------------------------------------------------------

- Completely Free of PyQt6 Signal/Slot Dependencies in Flet: The application uses a thread-safe Queue architecture to bridge the background Python engine and the UI rendering loop, preserving a complete architecture separation.
- Complete Academic Documentation: All Word manuals (`.docx`) in the docs directory have been updated programmatically to perfectly match the final Flet dashboard, replacing obsolete references to PyQtGraph or PyQt6 with Flet Canvas rolls and Queueing locks.
- One-Click Standalone Executables: GitHub Actions triggers precisely 1 build per release tag (`v*`) and uses PyInstaller to bundle the `flet-desktop` package and the ONNX models into standalone executables, ready to launch instantly on Windows and macOS.

4. VERIFICATION & TESTING PROCEDURES (HOW TO TEST ON WINDOWS & MAC)
-----------------------------------------------------------------------------

To ensure all deliverables are fully met, follow these platform-agnostic, step-by-step verification procedures on either Windows or macOS:

[Test 1] Launcher & Environment Self-Bootstrapping
  - Execution:
    * On Windows: Double-click 'Run_Windows.bat'.
    * On macOS: Double-click 'Run_macOS.command' (or run 'chmod +x Run_macOS.command && ./Run_macOS.command' in Terminal).
  - Expected Outcome: 
    * The terminal should launch, automatically check for Python, set up an isolated virtual environment ('venv'), pre-install all pinning requirements (including 'flet' and 'flet-desktop' to prevent import NameErrors), and start the application instantly with zero manual commands.

[Test 2] First-Launch Local Calibration Verification
  - Setup: If the application has been run before, delete or rename the local scaler file to simulate a brand-new user install:
    * Path: '~/.sro_optimizer/scaler_local_v2.pkl' (located in your User Profile home folder).
  - Execution: Run the application.
  - Expected Outcome:
    * The central circular gauge should show "Calibrating sensors" in amber text.
    * The progress percentage should count up from 1% to 100% over exactly 90 seconds.
    * At 100%, a desktop notification should slide out confirming: "🎯 Calibration Complete! Local system metrics calibrated successfully."
    * The file '~/.sro_optimizer/scaler_local_v2.pkl' should now appear on your disk with a non-zero file size.

[Test 3] Telemetry Pipeline & UI Responsiveness Test
  - Execution: Navigate the left sidebar across 'Dashboard', 'Analytics', and 'Settings'.
  - Expected Outcome:
    * Navigation transitions should be fluid, and the app must run continuously without any layout freezes.
    * Four real-time telemetry cards (CPU, Memory, Temp, Swap) must update every 1.0s.
    * Canvas charts must draw smooth rolling lines without crashing.
    * Under the 'Running Processes' card, the top 20 resource-consuming processes must refresh every 3 seconds, sorted in descending order of memory usage.

[Test 4] Stress Testing AI Bottleneck Forecasting
  - Setup: Open the 'Settings' page and ensure 'Auto-Pilot Mode' is turned OFF.
  - Execution: Induce a system resource stress spike. You can run multiple heavy apps (e.g., compile code, open 20 browser tabs, or run a benchmark utility).
  - Expected Outcome:
    * As the CPU and memory utilization surges above 80%, the 'AI Bottleneck Gauge' on the dashboard should react dynamically.
    * The predicted future CPU % and Memory % loads shown under the gauge should rise.
    * The confidence value should shift from green (low risk) to amber (moderate risk) and ultimately red (high load risk) as confidence spikes above 80%.

[Test 5] Autopilot & Safe Process Suspension Test
  - Setup: On the 'Settings' page, turn 'Auto-Pilot Mode' ON. Ensure you have a non-critical heavy user process running (e.g., an independent browser tab, text editor, or calculator).
  - Execution: Induce a bottleneck spike (above 80% threshold).
  - Expected Outcome:
    * Once the AI Confidence crosses 80%, the Action Engine should fire.
    * A warning alert will appear: "🤖 Auto-Pilot Activated — Autonomous Boost Enabled".
    * The top 3 resource-heavy user processes will be suspended safely.
    * Whitelisted processes (Python, SRO optimizer itself, DwM, Explorer, or System Services) MUST remain active and completely untouched.
    * Navigate to the 'Suspended Processes' card; the target processes will be listed with their exact suspension time.
    * After 5 minutes, verify that the watchdog timer automatically triggers and resumes the suspended processes, returning your system to its normal state.

[Test 6] Manual Override & Process Recovery Test
  - Setup: Turn 'Auto-Pilot Mode' OFF.
  - Execution:
    * Step 1: Click the green 'One-Click Boost' manual override button on the dashboard.
    * Step 2: Observe processes entering suspension in the list.
    * Step 3: Click the 'Undo Suspension' manual button.
  - Expected Outcome:
    * Clicking 'One-Click Boost' immediately suspends the top 3 heavy non-whitelisted processes and adds them to the list.
    * Clicking 'Undo Suspension' instantly resumes all suspended processes, clearing the suspended list and restoring full user-space execution.
